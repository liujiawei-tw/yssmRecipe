# 配方原料管理系統 V1.0

## 系統需求、資料架構、商業邏輯與 Vibe Coding 開發規格

> **用途**：本文件作為 IntelliJ IDEA + AI Coding Agent / GitHub Copilot
> 進行 Vibe Coding 的主要需求基準（Single Source of Truth）。
>
> **核心原則**：若開發過程發現需求矛盾、資料不足或商業規則不明確，先提出問題，不要自行猜測或改變規則。
>
> **V1 第一優先**：配方比例計算正確、可測試、可追溯。\
> **V1 第二優先**：配方版本 CRUD 與歷史保存。\
> **V1 第三優先**：商品庫存 → 生產需求 → 原料需求 → 原料庫存 →
> 缺料／請購。

------------------------------------------------------------------------

# 1. 專案背景

公司目前約有 **800～900 項商品**，每個商品都有固定商品代號。

目前資料來源：

1.  商品配方／成分比例：Excel。
2.  原料資料與原料庫存盤點：Excel。
3.  商品庫存：公司 ERP，可匯出商品庫存清單。
4.  原料庫存不是即時庫存，而是在生產前人工盤點。
5.  配方會不定期調整，舊版本必須保留。
6.  公司內部有多台電腦／多人使用。
7.  原先考慮 Excel +
    VBA，但多人協作、版本管理、資料一致性與未來擴充性較差，因此正式方向改為
    Web 前後端架構。
8.  Excel 保留作為 ERP／盤點資料的 Import / Export
    介面，而非正式資料庫。

# 6. 商品庫存與生產邏輯

每個商品有：

-   商品代號
-   商品名稱
-   安全庫存
-   最大倉位／最大庫存容量
-   ERP 庫存單位
-   包裝換算資訊

自動排程觸發：

``` text
currentStock < safetyStock
```

`currentStock == safetyStock` 不視為低於安全庫存。

預設目標：

``` text
targetStock = maxStock
```

預設建議生產量：

``` text
suggestedQuantity = max(maxStock - currentStock, 0)
```

例如：

``` text
安全庫存 = 50箱
最大倉位 = 100箱
目前庫存 = 35箱

35 < 50
→ 需要生產

建議生產量 = 100 - 35 = 65箱
```

------------------------------------------------------------------------

# 7. 手動指定生產量

除了系統建議，必須允許：

``` text
calculationMode = SYSTEM
calculationMode = MANUAL
```

系統應同時保留：

``` text
suggestedQuantity
plannedQuantity
```

例如：

``` text
系統建議：65箱
使用者實際指定：50箱
```

後續原料需求使用 `plannedQuantity`。

# 8. 商品包裝與 ERP 單位

已確認：

> 每個商品都能從商品包裝資料推導出「1 個 ERP 庫存單位 = 幾克」。

例如：

``` text
紅茶粉_3kg/包
ERP庫存單位 = 包
1包 = 3000g
```

``` text
50g大麥茶包_50g*40包/袋
ERP庫存單位 = 袋
1袋 = 50 × 40 = 2000g
```

商品名稱 `/` 後面的單位目前代表 ERP
庫存單位，但正式系統**不要依賴解析商品名稱作為唯一資料來源**，應建立結構化欄位。

生產重量：

``` text
productionWeightG
= plannedQuantity × gramWeightPerErpUnit
```

# 10. 配方基本概念

配方比例是**重量比例**，不是百分比。

例如：

``` text
1 : 7 : 3 : 4
```

表示四種原料的相對重量。

正式計算單位以克（g）為核心標準單位。

------------------------------------------------------------------------

# 11. 配方比例計算

假設：

``` text
A = 1
B = 7
C = 3
D = 4
```

比例總和：

``` text
totalRatio = 1 + 7 + 3 + 4 = 15
```

若目標重量：

``` text
targetWeight = 500g
```

則：

``` text
A = 500 × 1 / 15 = 33.333...
B = 500 × 7 / 15 = 233.333...
C = 500 × 3 / 15 = 100
D = 500 × 4 / 15 = 133.333...
```

各原料百分比：

``` text
A = 1 / 15 × 100 = 6.666...%
B = 7 / 15 × 100 = 46.666...%
C = 3 / 15 × 100 = 20%
D = 4 / 15 × 100 = 26.666...%
```

``` text

```

# 13. 基準重量與本次試算重量

每個配方／商品可有：

``` text
baseWeightG
```

例如：

``` text
500g
```

但基準重量不是每次計算的強制值。

使用者可以：

1.  使用基準重量。
2.  手動輸入其他重量。
3.  透過商品生產需求計算重量。
4.  新產品開發時臨時輸入任意重量試算。

例如：

``` text
baseWeight = 500g
targetWeight = 1275g
```

計算使用 `1275g`，不能修改原本 `baseWeight`。

------------------------------------------------------------------------

# 14. 比例 0 的規則

允許：

``` text
1 : 0 : 6 : 3
```

代表該原料：

> 目前不用，但保留這個位置。

比例 0： - 保留 RecipeVersionItem - 百分比 = 0% - 實際重量 = 0g -
可顯示在結果表 - 圓餅圖可排除 0 值 - 不可因比例 0 自動刪除原料

「刪除原料」與「比例設為 0」是不同操作。

------------------------------------------------------------------------

# 15. 無效配方驗證

禁止：

``` text
ratio < 0
```

如果：

``` text
0 : 0 : 0
```

則：

``` text
totalRatio = 0
```

必須拒絕計算。

如果沒有任何 Recipe Item，也拒絕計算。

如果：

``` text
targetWeight <= 0
```

拒絕計算。

# 16. 配方版本

目前版本格式：

``` text

```

例如：

``` text

```

例如：


``` text

```

# 18. 歷史配方保存

舊版本不可因新版本修改而改變。

例如：

2025：

``` text
A = 1
B = 2
C = 6
```

2026：

``` text
A = 1
C = 6
D = 3
```

查看 2025 歷史版本時，B 必須仍然存在。

因此版本資料採 Snapshot 思維：

``` text
Recipe
↓
RecipeVersion
↓
RecipeVersionItem[]
```

每個版本保存完整原料清單。

# 38. Recipe Calculation Engine

這是 V1 最重要的 Domain Logic。

建議：

``` text
domain/recipe/calculation/
├── RecipeCalculationService
├── RecipeCalculationRequest
├── RecipeCalculationResult
└── RecipeMaterialCalculation
```

核心算法：

``` text
totalRatio = Σ ratio

percentage_i = ratio_i / totalRatio

weight_i = targetWeight × percentage_i
```

Backend 必須是正式結果唯一來源。

Frontend 不可自行重新算一套正式結果。

不要在 Controller 寫配方計算。

------------------------------------------------------------------------

# 44. JPA vs JDBC 最終原則

正式選擇：

> **JPA / Hibernate 為主。**

理由： - CRUD 多 - Entity 關係清楚 - Spring Boot 整合成熟 - 維護成本較低

但不禁止 SQL。

需要複雜彙總或效能最佳化時可使用： - JPQL - Native Query - Projection -
JdbcTemplate

不要為所有簡單 CRUD 手寫 JDBC。

------------------------------------------------------------------------

例如：

``` text
V3__add_production_plan.sql
```

不要直接手動修改正式 DB Schema。
